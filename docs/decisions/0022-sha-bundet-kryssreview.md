# ADR 0022 – Kryssreview bundet til kode og base

Status: aktivert 15.11.2026 etter live aksept og kontroll av grenbeskyttelse; modellbegrensningen for Codex er dokumentert nedenfor.

T42 trenger en maskinelt kontrollerbar godkjenning fra påkrevde reviewere. PR-kommentarer alene kan være gamle, forfalsket av en forfatter eller gjelde en annen base.

Vi bruker `pull_request_target` med kun betrodd base-checkout for å sette pending, og en separat `workflow_run` for selve reviewet. Live testen ga 401 fra Anthropics OIDC-bytte på pull_request_target (upstream #713). Reviewkjøringen bruker sin egen main-SHA; kildekjøringens workflow-ID/sti, repo, event, forsøksnummer og vellykkede resultat kontrolleres via GitHub API. Nøyaktig én PR må fortsatt ha samme head og base, og basen må være checkout-commiten. Ingen kilde-artifacts lastes ned. Dette hindrer at et likt workflow-navn i en PR gir tilgang til hemmelighetene. Diffen leses som data, og review-agenten kjører aldri PR-kode. Den deterministiske gaten sammenligner head, base, test-merge-SHA og tittel før og etter review og setter status på head-commiten. En egen GitHub App er påkrevd kilde til statusen, slik at andre PR-workflows med statuses:write ikke kan forfalske godkjenning. App-nøkkelen ligger kun i environment `agent-review`, med tillatt deploy-gren nøyaktig `main`. Grenbeskyttelsen krever oppdatert base og CI.

Claude leverer en strukturert konklusjon. Codex-integrasjonen gir ikke en offentlig dokumentert status-API med modellvalg og norsk konklusjon. Vi validerer det observerte formatet fra den autentiserte Codex-boten: full head-SHA, fullført kodereview uten funn og ny reviewkvittering etter bestilling. Ukjent format blokkerer; en reaksjon godkjenner aldri. Gaten oversetter et gyldig rent resultat til «GODKJENT» og dokumenterer kilde/revisjon. Eieren bekreftet med skjermbilder 15.11.2026 at repoets innstillinger ikke tilbyr modellvalg. Kvitteringen oppgir heller ikke modellen. Integrasjonens leverandørstyrte modell brukes derfor som dokumentert avvik fra ønsket GPT-6.1 Sol (spec 19.5, Board #457); akseptbeviset bekrefter bot og kodeversjon, ikke modellidentitet. Dette kontrolleres igjen hvis leverandøren eksponerer modellvalg eller metadata.

Tre mislykkede ulike head-SHA-er siden siste godkjenning eskaleres til T42 på Board med berørt PR som referanse. Omkjøring av samme kode er ikke en ny reviewrunde. Varslingen bruker en separat Board CI-identitet; nettlesersesjoner og personlige lokale tokens kopieres ikke til GitHub. Manglende varslingstilgang gir rød sjekk. Rundekommentarer må komme fra den dedikerte App-boten, aldri den delte github-actions-boten. Varslingen er minst én gang: dersom Board lykkes og lagring av kvitteringen feiler, kan neste forsøk gi en duplikat med samme PR-referanse.

Dette medfører avhengighet til et observert Codex-format som må testes ved integrasjonsendringer. Grenbeskyttelsen aktiveres først etter separate test-PR-er; eieren merger alltid. Se `docs/runbook.md` for aktivering og feilhåndtering.

Claude leser bare arbeidsmappen i restricted-modus. Diff og kontekst ligger under `.review/`. Publiseringsverktøyet avviser tekst med verdier på minst 16 tegn fra miljøvariabler med TOKEN, SECRET, KEY, PASSWORD eller CREDENTIAL i navnet eller kjente tokenmønstre. Ukjent mergeability ventes på i inntil 30 sekunder, før kjøringen feiler lukket.

App-en og trigger-tokenet trenger Pull requests: write for PR-kommentarer. Live API svarte 403 med Issues: write alene. Tokenene er fortsatt avgrenset til ekko, og App-en har ikke Contents: write. Claude beholder egen App-identitet og restricted-verktøy; hendelsesbyttet fritar ikke fra runbookens live aksept.

Lesetilgang avgrenses med `--restricted` til arbeidsmappen, med ekstra deny for `.git`, `/proc` og `/tmp`. Hjemmemappen kan ikke blokkeres samlet: checkout på GitHub ligger under `/home/runner`. En ekte før/etter-test viste at repo-lesing da virket mens `.git` og utenforliggende filer fortsatt ble nektet. Publisering returnerer hele den kanoniske kvitteringen; modellen skal kopiere den uendret, og gaten beholder eksakt sammenligning mot Claude-kommentaren.
